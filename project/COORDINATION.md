# Two-Agent Coordination Protocol

- Status: APPROVED (D-006, CC WEBDEV v2.0; originates from Conceptiones D-088)
- Applies to: Claude Code and ChatGPT/Codex working in this repository (and in every client repo cloned from it). Dan Andrei is the arbiter.

## Lanes

- **Dan:** creative direction, assigns owners, approves copy, assets, scope, acceptance and launch.
- **Claude Code:** implementation, builds, fixes, PRs. Default owner of every implementation task.
- **ChatGPT/Codex:** research with live browsing, strategy, copy, specifications, and QA reports at milestones (before a release, not after every task). Implements only a task Dan explicitly assigns to it in `project/TASK_LOCKS.md`.

## One owner per task

`project/TASK_LOCKS.md` lists every task with its owner (`CLAUDE`, `CODEX` or `NONE`), branch, claim time and the files it may touch.

1. Before starting: `git pull --ff-only` on `main` and read `TASK_LOCKS.md`. If the task is owned by someone else, or Dan has not authorized it as `IMPLEMENT`, stop and tell Dan.
2. Claim: commit only your lock row to `main` (owner, branch, files you will touch) and push. If the push is rejected, pull, re-read the file and stop if another agent claimed first.
3. Work on a branch named `claude/TASK-xxx` or `codex/TASK-xxx`, created from current `main`. Never commit to `main` except lock rows and merges Dan approved.
4. Touch only the files in your lock row. If you need another file, update your row first. If another row overlaps, stop and ask Dan.
5. Shared files (`AI_HANDOFF.md`, `06_DECISIONS.md`) are edited only at merge time, by the agent merging, after rebasing on the latest `main`. Per-task detail goes only in your own `project/tasks/TASK-xxx.md`.
6. On merge: set the owner to `NONE`, the status to `IMPLEMENTED`, delete the branch, add one line to `AI_HANDOFF.md`.
7. Two agents never work on the same task in parallel, not even on separate branches.
8. In doubt, do not guess: write an AMBIGUITY in your task file, leave the task at `REVIEW`, ask Dan.

## Statuses and severities

Statuses, exactly: DRAFT, REVIEW, APPROVED, IMPLEMENT, IMPLEMENTED, QA, DONE. `DRAFT` and `REVIEW` do not authorize implementation. Severities: P0, P1, P2. Do not infer approval or completion from chat history; GitHub records the state.

## AMBIGUITY format

- **AMBIGUITY:**
  - Document/section affected:
  - Question: the exact open question.
  - Impact: what cannot be implemented, or what decision is blocked, until it is resolved.
  - Decision needed from: normally Dan Andrei.

## Handoff rules (keep reading cost low)

- `AI_HANDOFF.md` stays at 60 lines or fewer: base commit, task statuses, blockers, next step. No history.
- Each task has `project/tasks/TASK-xxx.md` (template in `project/tasks/_TEMPLATE.md`), 15 lines or fewer, naming the exact files to read.
- Read only the files the task file names. Do not re-scan the repository.
- Run `bash scripts/qa.sh` and report failures only. No screenshots or full command output in reports.
- History is archived in `project/archive/`; it is read only on request.
- Changelog is generated by `bash scripts/changelog.sh`; do not hand-write it.
- Report format to Dan, under 12 lines: task, status, files changed, check result, blockers, next step.
